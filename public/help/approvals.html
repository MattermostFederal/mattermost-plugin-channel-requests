Approving requests

Approve or deny channel requests from the approval channel.

Who can approve

System Admins can always approve. If the admin enabled Team Admins can approve requests, Team Admins of the approval team can too. Only a System Admin can approve a request they made themselves.

A request an AI agent filed for someone arrives the same way and names that person as the requester. Agents can't approve or deny.

Acting on a request

Each request is posted in the configured approval channel with Approve and Deny buttons.

ActionWhat happens
ApproveCreates the channel, adds the requested members, promotes the channel admins, and posts a welcome message that @-mentions everyone added.
DenyCloses the request. The requester is notified by direct message.

Requests that can't be approved as they stand

Before creating the channel, Approve checks the request again. If one of these applies, you'll see a private message, the request stays pending and the card keeps its buttons, so you can deny it:

  • The requester's account is no longer active. Deny this request instead.
  • The requester is no longer a member of the team. Deny this request instead.
  • The channel name no longer matches the configured prefixes. Deny this request and ask the requester to submit it again.

If the requester can't be checked at that moment, you'll see Could not check the requester right now. Try again in a moment. instead.

Channel Admin requests get the same check before anyone is promoted: if the requester's account is no longer active, or they've left the channel (System Admins excepted), you'll see The requester's account is no longer active. or The requester is no longer a member of the channel. and the request stays pending so you can deny it. See Troubleshooting.

Expired requests

A request that wasn't reviewed within the configured Request expiry (days) can't be approved. Clicking either button on it replies This request has expired., marks the card ⌛ Expired: not reviewed within N days. and sends the requester a direct message so they can submit it again. See Troubleshooting.

Auto-approved requests

Requests from System Admins and from users on the auto-approve list skip this step: the channel is created immediately, with no Approve/Deny card.

Audit trail

If an audit channel is configured, every approve and deny posts an audit line there so there's a durable record of who acted on what.
