Slash command & Agents

Request channels and Channel Admins from the message box, or ask an AI agent to do it.

The /channel-request command

/channel-request on its own opens the request form. Add a subcommand to do the same things from the message box. Replies are only visible to you.

CommandWhat it does
/channel-requestOpens the channel request form.
/channel-request create <prefix> <Channel name> [options]Requests a channel in the current team without the form.
/channel-request admin @user [@user ...]Asks for those channel members to be made Channel Admins of the channel you run it in.
/channel-request prefixesLists the channel prefixes you can use, with each one's description and suffix rule.
/channel-request listLists your pending requests, with their IDs and when they expire.
/channel-request approve <request ID>Approves a request, as its Approve button would.
/channel-request deny <request ID>Denies a request, as its Deny button would.
/channel-request helpShows the usage message.

An unknown subcommand replies Unknown subcommand `name`. followed by the usage message.

/channel-request create

/channel-request create <prefix> <Channel name> [--suffix <suffix>] [--purpose <text>] [--private] [--members @user ...] [--admins @user ...]

The prefix comes first, typed exactly as /channel-request prefixes lists it (for example team-). Then comes the channel name, which can be several words, then any options in any order. Each option takes the words up to the next --, and each can be given only once.

OptionWhat it does
--suffix <suffix>The URL part after the prefix, as one word. Leave it out to generate it from the channel name.
--purpose <text>A short description of the channel.
--privateMakes the channel private. Without it the channel is public.
--members @user ...Users who become regular members on approval. If you list exactly one member and no --admins, that member is made a Channel Admin, so the channel always has someone who can manage it.
--admins @user ...Users who become Channel Admins on approval.

For example:

/channel-request create team- Marketing Team --purpose Campaign planning --members @alice @bob --admins @carol
/channel-request create ops- SRE On-call --suffix sre-oncall --private

The request goes through the same approval as the form, and you get the same confirmation. If you're a System Admin or on the auto-approve list, the channel is created at once and the reply is Created channel ~name.

Limits of the command

A channel name or purpose can't contain a word that starts with --, and extra spaces or line breaks in the purpose become single spaces. Use the form if you need either.

/channel-request admin

/channel-request admin @user [@user ...]

Run it in the channel itself. Everyone you name must already be a member of it. The request goes to the System Admins and the Team Admins of the channel's team. If you're a System Admin or on the auto-approve list, they're promoted at once.

ReplyWhat to do
Name at least one channel member…Add at least one @user.
everyone you nominate must already be a member of the channelAdd them to the channel first.
channel not found, or you are not a member of itRun it from a channel you belong to.
Channel Admins can only be requested for public or private channels, that channel is archivedDirect and group messages and archived channels can't have Channel Admins.
you already have a pending Channel Admin request for these people in this channelWait for the existing request to be reviewed.

/channel-request prefixes

Lists every prefix your admin configured, with its description and, where there is one, its suffix rule. Use these exactly with create.

/channel-request list

Lists the channel and Channel Admin requests you made that are still waiting for review, oldest first. Each line shows what you asked for, the day you submitted it (in UTC), the day it expires if your admin set an expiry, and its request ID. A request that expired before anyone reviewed it is shown as expired (an approver can close it). A request submitted before the plugin started recording submission times shows submitted before the upgrade and doesn't expire. If nothing is waiting, the reply is You have no pending requests.

At most 50 requests are shown, followed by ...and N more when there are others.

Approved and denied requests aren't listed. The bot sends you a direct message with each outcome.

/channel-request approve

/channel-request approve <request ID>

Approves a request without clicking its card. The request ID is at the bottom of the approval card, after Request ID:. The command makes the same checks as the Approve button, in the same order, and the reply is only visible to you. When it succeeds, every copy of the approval card is updated, the same as after a click. See Approving requests for who can approve.

/channel-request deny

/channel-request deny <request ID>

Denies a request, as its Deny button would. It works the same way as approve.

/channel-request help

Shows the usage message for every subcommand.

Agents tools

When a System Admin turns on Offer tools to Agents, an agent from the Mattermost Agents plugin can file requests for you. Ask it in plain words, for example "request a private channel called Marketing Team under team- and add @alice". The agent acts as you, so the request follows the same rules as the form: you must be a member of the team or channel, the prefix must be one your admin configured, and the request goes to the approvers unless you are a System Admin or on the auto-approve list.

ToolWhat it does
list_prefixesLists the channel prefixes you can use, like /channel-request prefixes.
request_channelRequests a new channel, like the form or /channel-request create.
request_channel_adminAsks for channel members to be made Channel Admins, like /channel-request admin.
list_my_requestsLists your pending requests, like /channel-request list.
get_request_statusLooks up one pending request by ID. It finds your own requests, and requests you can approve.

In the Agents plugin's settings, the tools are listed with the plugin's prefix, for example com_mattermostfederal_channel-requests__request_channel. If an agent doesn't offer them, see Agents tools not showing.

Agents can't approve

No agent can approve or deny a request. That stays with the approvers, on the approval card or with /channel-request approve and deny.
