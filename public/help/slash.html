Slash commands

Same requests as the hub and native menus, from the message box. Replies are only visible to you.

The /mattermost-request-hub command

CommandWhat it does

/mattermost-request-hub helpLists every subcommand and its arguments, with a link to this documentation.
/mattermost-request-hub channelOpens the Request a Channel form, or with arguments requests a channel without it. /mattermost-request-hub on its own opens the form too.
/mattermost-request-hub channel-adminOpens the Request Channel Admin form, or with @user names asks for those channel members to be made Channel Admins of the channel you run it in.
/mattermost-request-hub prefixesLists the channel prefixes you can use, with each one's description and suffix rule.
/mattermost-request-hub teamOpens the Request a Team form, or with arguments requests a new team without it.
/mattermost-request-hub team-adminOpens the Request Team Admin form, or with @user names asks for those team members to be made Team Admins of the current team.

/mattermost-request-hub botOpens the Request a Bot form, or with a username and display name requests the bot without it.

/mattermost-request-hub webhook-outgoingOpens the outgoing webhook form, or with a channel, display name and callback URL requests the webhook without it.

Each request subcommand opens its form when you give it no arguments. With arguments, it files the request directly, with the same checks, approvers and confirmation as the form. See Typing arguments for quotes and lists. A request type a System Admin has turned off in the System Console replies that it is disabled, for example Channel requests are currently disabled by an administrator., and help leaves it out. Requests made with a slash command always go to the approvers, even when a System Admin runs it. An unknown subcommand replies Unknown subcommand `name`. followed by the list above.

Replies with a link to the overview of this documentation.

/mattermost-request-hub help

Lists every subcommand and its arguments, with a link to this documentation.

/mattermost-request-hub channel

On its own, opens the Request a Channel form. With a prefix and a channel name, it requests the channel in the current team without the form.

Requesting a channel without the form

/mattermost-request-hub channel <prefix> <Channel name> [--suffix <suffix>] [--purpose <text>] [--private] [--members @user ...] [--admins @user ...] [--category <name>]

The prefix comes first, typed exactly as /mattermost-request-hub prefixes lists it (for example team-). Then comes the channel name, which can be several words, then any options in any order. Each option takes the words up to the next --, and each can be given only once.

OptionWhat it does
--suffix <suffix>The URL part after the prefix, as one word. Leave it out to generate it from the channel name.
--purpose <text>A short description of the channel.
--privateMakes the channel private. Without it the channel is public.
--members @user ...Users who become regular members on approval. If you list exactly one member and no --admins, that member is made a Channel Admin, so the channel always has someone who can manage it.
--admins @user ...Users who become Channel Admins on approval.
--category <name>Sidebar category to place the channel in on approval. It can be several words; a missing category is created.

For example:

/mattermost-request-hub channel team- Marketing Team --purpose Campaign planning --members @alice @bob --admins @carol
/mattermost-request-hub channel ops- SRE On-call --suffix sre-oncall --private --category Operations

The request goes through the same checks and approval as the form, and you get the same confirmation.

/mattermost-request-hub channel-admin

On its own, opens the Request Channel Admin form. With @user names, it files the request for the channel you run it in.

Requesting Channel Admin without the form

/mattermost-request-hub channel-admin @user [@user ...]

Run it in the channel itself. You must be a member of it (System Admins excepted), and everyone you name must already be a member too; the request never adds anyone to the channel. The request goes to the System Admins and the Team Admins of the channel's team, the same approvers as the form. The command isn't hidden from people who already admin the channel, but they can manage it directly instead.

ReplyWhat to do
Name at least one channel member...Add at least one @user.
everyone you nominate must already be a member of the channelAdd them to the channel first.
channel not found, or you are not a member of itRun it from a channel you belong to.
Channel Admins can only be requested for public or private channels, that channel is archivedDirect and group messages and archived channels can't have Channel Admins.
you already have a pending Channel Admin request for these people in this channelWait for the existing request to be reviewed.

/mattermost-request-hub prefixes

Lists every prefix your admin configured, with its description and, where there is one, its suffix rule. Use these exactly with /mattermost-request-hub channel.

The other request types

On their own, these subcommands open the request form for their type. With arguments, they file the request without it. Team Admin, team member and guest requests are for the team you run the command in. Name channels as ~channel, using the name from the channel's URL, and users as @user. The form, approvers and what happens on approve are described on each type's page.

/mattermost-request-hub team

/mattermost-request-hub team <Team name> [--name <url name>] [--description <text>] [--invite-only] [--team-admin]

The team name can be several words. --name is the URL name; leave it out to generate it from the team name. Without --invite-only the team is open. --team-admin makes you a Team Admin of the new team. See Teams.

/mattermost-request-hub team-admin

/mattermost-request-hub team-admin @user [@user ...]

Asks for those people to be made Team Admins of the current team. You must be a member of the team. See Teams.

/mattermost-request-hub team-member

/mattermost-request-hub team-member @user [@user ...] [--reason <text>]

Asks for those users or bots to be added to the current team. See Team members.

/mattermost-request-hub team-guest

/mattermost-request-hub team-guest <email> --channels ~channel [~channel ...] [--reason <text>]

Asks for a guest invite to those channels of the current team. See Guest invites.

/mattermost-request-hub bot

/mattermost-request-hub bot <username> <Display name> [--description <text>] [--owner @user]

The username is one word; the display name can be several. Access tokens and webhooks for the bot are only in the form. See Bots.

/mattermost-request-hub webhook-incoming

/mattermost-request-hub webhook-incoming ~channel <Display name> [--description <text>]

Requests an incoming webhook that posts to that channel. See Webhooks.

/mattermost-request-hub webhook-outgoing

/mattermost-request-hub webhook-outgoing ~channel <Display name> --callback <url> [--description <text>]

Requests an outgoing webhook for that channel. See Webhooks.

For example:

/mattermost-request-hub team Field Support --description Support for field teams --invite-only
/mattermost-request-hub team-member @alice,@bob --reason Joining the ops rotation
/mattermost-request-hub team-guest guest@example.com --channels ~town-square ~vendor-chat
/mattermost-request-hub bot build-bot Build Bot --description Posts build results --owner @carol
/mattermost-request-hub webhook-outgoing ~deploys Deploy Hook --callback https://ci.example.com/hook

If something is wrong, the reply starts Could not read the request:, says what, and repeats the usage line; nothing is submitted. A name that isn't a user, or a channel that isn't a public channel of the team or a private one you are in, replies unknown user: name or unknown channel: ~name.

Typing arguments

  • Each option takes the words up to the next word that starts with --, so names, purposes and descriptions can be several words.
  • Put quotes around text that should stay as typed, for example --purpose "--draft-- plans". Inside quotes, a word that starts with -- is just text. The quote marks themselves are not saved. Curly quotes work too.
  • Separate users or channels with spaces or commas: @alice @bob, @alice,@bob and @alice, @bob mean the same.
  • A long dash that your device typed in place of -- works like --.

Channel and Channel Admin requests can also be filed by an AI agent; see AI agents. If a reply isn't clear, see Troubleshooting.

Markdown sources for contributors live in the plugin repo under docs/ (including admin-guide.md for System Console setup).
