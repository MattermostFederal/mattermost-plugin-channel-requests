Slash commands

Same requests as the hub and native menus, from the message box. Replies are only visible to you.

CommandWhat it does
/mattermost-request-hub docsLinks to this documentation (overview).
/mattermost-request-hub helpLists every subcommand and its arguments, with a link to this documentation.
/mattermost-request-hub channelOpens the Request a Channel form. /mattermost-request-hub on its own does the same.
/mattermost-request-hub channel <prefix> <Channel name> [options]Requests a channel in the current team without the form. See below.
/mattermost-request-hub channel-adminOpens the Request Channel Admin form.
/mattermost-request-hub channel-admin @user [@user ...]Asks for those channel members to be made Channel Admins of the channel you run it in. See below.
/mattermost-request-hub prefixesLists the channel prefixes you can use, with each one's description and suffix rule.
/mattermost-request-hub teamOpens the Request a Team form.
/mattermost-request-hub team-adminOpens the Request Team Admin form.
/mattermost-request-hub team-memberOpens the Request Team Members form.
/mattermost-request-hub team-guestOpens the Request Guest Invite form.
/mattermost-request-hub botOpens the Request a Bot form.
/mattermost-request-hub webhook-incomingOpens the incoming webhook form.
/mattermost-request-hub webhook-outgoingOpens the outgoing webhook form.

A request type a System Admin has turned off in the System Console replies that it is disabled. Requests made with a slash command always go to the approvers, even when a System Admin runs it. An unknown subcommand replies with the list above.

Requesting a channel without the form

The prefix comes first, typed exactly as /mattermost-request-hub prefixes lists it (for example team-). Then comes the channel name, which can be several words, then any options in any order. Each option takes the words up to the next --.

OptionWhat it does
--suffix <suffix>The URL part after the prefix, as one word. Leave it out to generate it from the channel name.
--purpose <text>A short description of the channel.
--privateMakes the channel private. Without it the channel is public.
--members @user ...Users who become regular members on approval.
--admins @user ...Users who become Channel Admins on approval.
--category <name>Sidebar category to place the channel in on approval. It can be several words; a missing category is created.

For example:

/mattermost-request-hub channel team- Marketing Team --purpose Campaign planning --members @alice @bob --admins @carol
/mattermost-request-hub channel ops- SRE On-call --suffix sre-oncall --private --category Operations

The request goes through the same checks and approval as the form, and you get the same confirmation. If something is wrong, such as an unknown prefix, an unknown @user or a suffix that breaks the prefix's rule, the reply says what, and nothing is submitted.

Limits of the command

A channel name, purpose or category can't contain a word that starts with --, and extra spaces or line breaks in them become single spaces. Use the form if you need either.

Requesting Channel Admin without the form

Run /mattermost-request-hub channel-admin @user [@user ...] in the channel itself. You must be a member of it (System Admins excepted), and everyone you name must already be a member too; the request never adds anyone to the channel. The approvers are the same as for the form. The command isn't hidden from people who already admin the channel, but they can manage it directly instead.

Markdown sources for contributors live in the plugin repo under docs/ (including admin-guide.md for System Console setup).
