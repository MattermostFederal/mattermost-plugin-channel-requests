Troubleshooting

What a message means, and what to do about it.

"Channel requests aren't configured yet"

The channel request form, /channel-request, create, prefixes and the Agents list_prefixes tool show Channel requests aren't configured yet. Ask a System Admin to define at least one channel prefix in System Console → Plugins → Channel Requests. The Agents request_channel tool says plugin is not configured: an admin must define at least one channel prefix.

Cause: no domain prefix is defined. Every request needs one. Fix: a System Admin adds at least one prefix, for example with Load preset. See Admin Setup.

Requests arrive as direct messages to System Admins

Cause: the approval channel isn't set, or the configured channel no longer exists, is archived, or isn't in the approval team. Rather than drop the request, the plugin sends it by direct message to every active System Admin. When a channel is configured but can't be used, the server log also has the warning configured approval channel unavailable; falling back to System Admins.

Fix: set Approval team and Approval channel in the plugin settings to an existing channel in that team. Any one System Admin can act on a DMed request; after that, the buttons on the other copies reply This request has already been handled.

If no System Admin can receive the message either, the requester sees could not send your request to the approvers; try again or contact a System Admin.

"This request has expired"

Cause: the request wasn't reviewed within Request expiry (days). Approve and Deny both reply This request has expired., the card is marked ⌛ Expired: not reviewed within N days., and the requester gets a direct message.

Fix: the requester submits it again. Raising the expiry also applies to requests already pending; 0 turns expiry off. See Admin Setup.

"You have N pending requests waiting for review"

Cause: the requester is at Pending requests per user for that kind of request (new channels and Channel Admins are counted separately). Expired requests no longer count.

Fix: wait for an approver to act on some, or for them to expire. A System Admin can raise the limit, or set it to 0 for no limit.

A related message, you already have a pending request for ~name in this team (or …a pending Channel Admin request for these people in this channel), means the same request is already waiting. It doesn't need to be submitted twice.

Approve says the requester is no longer active or a member

Approve checks the request again before acting. You'll see a private message, and the request stays pending with its buttons:

  • The requester's account is no longer active. Deny this request instead.
  • The requester is no longer a member of the team. Deny this request instead.
  • The requester is no longer a member of the channel. Deny this request instead. (Channel Admin requests)
  • The channel name no longer matches the configured prefixes. Deny this request and ask the requester to submit it again.

Fix: deny the request. Deny is never blocked. See Approving Requests.

For a Channel Admin request, if the nominees have left the channel by the time it's approved, the card says nobody was promoted: the nominees are no longer members and the requester is told.

"Try again" messages

Could not check the requester right now. Try again in a moment., could not load your account; try again and could not save your request; try again mean a lookup or save failed for a moment.

Fix: try again. If it keeps happening, check the server log for an error from the plugin.

No audit lines in the audit channel

Cause: Audit channel ID must be an existing, unarchived private channel. Anything else (a public channel, a wrong ID, an archived channel) is skipped, and the server log has the warning the audit channel must be an existing private channel; skipping audit posts.

Fix: create a private channel, copy its ID (channel menu → View Info), and paste it into the setting. If the channel is right but a post still fails, the server log has audit post failed with the reason.

Agents tools not showing

If an agent doesn't offer to file channel requests, check, in order:

  • Offer tools to Agents is on in the Channel Requests settings. It's off by default.
  • The Mattermost Agents plugin is installed and enabled.
  • The tools are allowed in the Agents plugin's settings. They're listed with this plugin's prefix: com_mattermostfederal_channel-requests__list_prefixes, com_mattermostfederal_channel-requests__request_channel, com_mattermostfederal_channel-requests__request_channel_admin, com_mattermostfederal_channel-requests__list_my_requests and com_mattermostfederal_channel-requests__get_request_status.

See Agents tools for what each one does.

Exercise mode

"Exercise mode is off": turn on Enable exercise mode in the plugin settings. Only System Admins can run the command.

"The username @exercise-… is taken by an account that isn't exercise data": a real account has a persona's username. Populate creates nothing in that case. Rename that account, or change the persona's role in the exercise scenario.

"This server or team only allows accounts with email addresses at …": personas use addresses at exercise.invalid, a domain that never receives mail, and Mattermost only lets accounts from the allowed domains join a team. While you run the exercise, add exercise.invalid to Restrict account creation to specified email domains in the System Console, or to the team's allowed domains, whichever the reply names.

"A channel named ~… already exists in this team": a channel, archived or not, already has a name the scenario needs. Rename it, or change the scenario's suffix.

Status says the exercise is populating when no populate is running: an earlier populate stopped partway. The server log has failed to populate exercise data with the reason. Run /channel-request exercise teardown, which removes whatever it created, then populate again. For five minutes after a populate stops, teardown answers a populate is still running in this team, since it can't tell a stopped populate from a slow one. Wait and run it again.

Teardown says some items could not be removed, or status says a teardown started but didn't finish: the record of the exercise is kept, so run teardown again. The server log names each item that failed. A request stored under an exercise request's ID that isn't exercise data is always left alone and reported this way.
